# POC 结果：几何稳定不等于滚动体验通过

2026-10-26，macOS 上的 Chrome 156，使用 Vite 生产构建。输入为真实 Haklex `RichRenderer` 和图片 renderer。正式包及编辑器未修改。

完成 65 组、8710 个有效 rAF 样本：1440×1000 桌面视口的 20 组矩阵重复两轮，1040×768 窄视口的 20 组矩阵，以及 2000 块文档的 5 个实测回收场景。每组 134 个有效样本，锚点丢失为 0；稳定基线和过期高度负对照均通过校准。机器可读数据及被测源码 hash 在 [results.json](./results.json)。

## 复杂节点追加验证

按后续要求加入了真实动态计数器、答题组件、内外层可折叠面板、面板内图片、表格、多级列表、引用与静态代码块。动态组件使用现有 `counter.mjs`、`quiz.mjs` 和 Shadow DOM mount 协议。

更新后完成 29 组、3886 个有效样本：24 组宽屏完整矩阵、4 组窄屏复杂场景，以及 1000 块复杂文档的实测模式。包含 9 组状态往返检查；每组均无锚点缺失。数据和源码 hash 独立保存在 [complex-results.json](./complex-results.json)，上一轮数据保持原样。

| 操作后滚走再返回     | 实测模式     | 直接卸载负对照 |
| -------------------- | ------------ | -------------- |
| 展开外层和内层面板   | 都保持展开   | 都恢复收起     |
| 将默认展开的面板收起 | 保持收起     | 又恢复展开     |
| 计数器点击三次       | 保持 3       | 重置为 0       |
| 答题组件作答         | 答题结果保留 | 答题结果丢失   |

实测模式还确认了：目标块在离屏后执行了停用和恢复，details DOM 与动态组件实例始终连接在文档中。完整渲染与 CSS 控制组也保留状态，直接卸载的两组负对照均检出了状态丢失。另验证了持有焦点的动态组件不会被停用，明暗主题更新不会重置计数或答题结果；24 次原生滚轮往返后状态同样保持。

实现策略是普通块继续卸载，有状态的 details/dynamic 内容保留实例，离屏只隐藏内部内容并保持外层实测占位。**它保留了 DOM、Shadow DOM 与副作用，不等于释放了这些组件的内存。** 360 块文档有约 117 个离屏内容盒保留；1000 块样本约 332 个。

复杂场景后续的 134 帧滚动采样中，实测模式落点位移为 0px；窄屏 CSS 模式测到 220px。但交互阶段恢复时曾出现约 824–829px 的高度差及补偿，已单独记录，不能把后续采样的 0px 解读为所有交互都无高度变化。上一轮的合成滚动空白和全量失效长帧问题也没有由本次状态保留策略解决。

本轮 POC 范围类型检查、lint 和生产构建通过。明暗主题以及答题组件可见时的 axe 检查没有确认违规项，但存在因部分内容被遮挡而无法自动判定的对比度项目；不将它当作完整无障碍验收。暂未验证替换整份文档 JSON 后的视图状态持久性、任意远程组件的后台更新、Safari 或编辑态。

原始记录位于 `/tmp/haklex-virtualization-poc/complex-{desktop,narrow,large}.json`；`complex-native.webm` 保存原生滚轮录像，`complex-focus.json`、`complex-theme.json` 和 `complex-native-state.json` 保存额外行为检查。

## 观察

下表是视口落点锚点在主动滚动后、随后一帧的最大额外位移，不是所有内容的绝对位置变化。

| 场景                 | CSS 估高，窄视口 / 360 块 | 实测回收，全部已测配置的最大值 |
| -------------------- | ------------------------: | -----------------------------: |
| 不同长度文字         |                     484px |                            0px |
| 横图 / 竖图混排      |                     484px |                            0px |
| 未知尺寸图片延迟加载 |                 1047.42px |                         0.39px |
| 滚动中改变栏宽       |                     484px |                         0.41px |
| 离屏图片改为竖图     |                  683.77px |                         0.33px |

宽屏下，CSS 的固定布局文字和图文场景没有测到落点位移；但文档 scrollHeight 分别变化了 14824px 和 22454px。因此“CSS 必然让可见文字抖动”过于绝对，抖动与视口、内容和触发时机有关；滚动总高度变化也应与阅读落点位移分开。

延迟无尺寸图片在完整渲染基线中也产生了超过 2000px 的位移，这是内容真实变高。实测方案以 JS 锚点补偿将当前落点位移压到了亚像素级；滚动前、此时可能已离开视口的另一处文字仍可移动约 369px。完整数据保留了这两种指标，不能只引用较小的一个而声称全文没有位置变化。

首轮 65 组中的实测回收恢复高度差均为 0；固定图文 360 块文档曾只保留约 7 块内容挂载。这个数字只表示内部 React 子树的挂载情况，完整文档模型和块壳仍然保留，没有证明内存按相同比例下降。

## 真实滚轮录像推翻了“零位移就是通过”

在 1040×768 窄视口中，另通过 CDP 在滚动区域坐标发送了 24 次原生滚轮事件，每次 1400px，实际从 0 滚到 16800px 后返回。CSS 和实测模式均录制了录像，并检查了截图序列。

**两种模式都出现了短暂空白或占位帧。** 实测模式 DOM 占位采样虽然是 0，录像仍然能看到这些帧，说明主线程采样不能完整覆盖合成滚动过程。原生滚轮过程中，CSS 的 scrollHeight 变化 7798px，实测模式为 0，但后者仍未解决全部视觉问题。

本次证据保存在 `/tmp/haklex-virtualization-poc/`：

- `desktop-production.json`：宽屏两轮完整逐帧数据。
- `narrow-production.json`：窄屏完整逐帧数据。
- `large-production.json`：2000 块文档完整逐帧数据。
- `native-css.webm`、`native-measured.webm`：15fps 保存的原生滚轮录像。Chrome 分别提供了 75 / 81 个捕获帧，保存时降采样；不构成逐个合成帧的证明。
- `native-css-contact.png`、`native-measured-contact.png`：用于检查空白的截图序列。

原生滚轮可用 [native-wheel.mjs](./native-wheel.mjs) 复现。完整原始文件为本机临时证据；长期保留的测量摘要是本目录的 `results.json`。

## 全量失效的代价

2000 块文档中，普通图文滚动采样的最长间隔约 18ms，但改变宽度时出现约 394ms 的间隔，离屏图片更新时约 455ms。当前 POC 在失效时恢复并测量全文；图片更新还触发了完整 headless 解析和 React 输出重建。这些数字是这个直接实现的代价，不能解释为所有实测虚拟化都必然如此。

下一轮值得验证的是：按脏块失效、宽度变化时的调度，以及高速滚动下的提前恢复/保留策略；同时检查图片重新挂载后的加载态。当前结果不足以批准接入正式编辑器。

## 检查与限制

- 独立入口的生产构建、POC 范围 TypeScript 检查、ESLint 和 Prettier 检查通过。
- 仅调整 ARIA 和焦点语义后，补跑图文场景仍为 0px 落点位移；明暗主题 axe 检查均为 0 项违规。原始测量与最终源码 hash 分别保存在摘要中。
- 全 demo TypeScript 检查仍有未修改文件 `src/pages/extensions/details/LiteXmlImport.tsx:24` 的 `SerializedLexicalNode.children` 错误。
- 未测 Safari、WKWebView、真实触控惯性、IME、编辑选区、撤销、协作、浮动绕排和嵌套编辑器。
- 几何探针本身读取布局，也没有隔离所有机器负载；不能将最长帧或挂载数量当作完整性能基准。
- POC 保留首次完整布局成本，整块回收会影响原生查找与跨块复制，尚不可投产。
